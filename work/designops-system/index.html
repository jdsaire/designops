The story
Act 01 · The Problem

Most strategy dies at the slide.

Describe

Someone describes a product —

Build

— and someone else, months later, builds a lesser version of it.

The distance between the two is where good work goes to die.

I spent the first part of my career on the describing side of that handoff.

Then AI removed the barriers. Two honest options: watch it happen to my profession — or take it by the horns.

Role — Sole owner Duration — 2025 to present Scope — Strategy → design → build → operation

A design file cannot misbehave — it sits still and looks perfect. Only a live product can drift, break, age, or hold. That is why this case's evidence is a running system rather than a picture of one: it is the only format in which governance claims can actually fail, and therefore the only format in which they mean something.

Act 02 · The Reinvention

I learned to build — then made building answer to my standard.

Stop 1

Stop 2

Stop 3

The new method

Act 04 · The Architecture

The evidence is public — and you're standing in it.

This is not a case about a product I once touched. The evidence is the site itself: live, versioned, and open to inspection. Four claims, each one checkable.

Ten building blocks, one standard

Every section of this site is built from reusable components under one standard — so nothing drifts, and new pages inherit quality instead of reinventing it.

Ten reusable organisms — navigation, hero, work cards, capability carousel, timeline, contact, and footer among them — each held to correct adoption of the global token layer. The structure beneath is semantic: header, nav, main, section, and footer landmarks, a single top-level heading, and a clean hierarchy below it, so browsers, assistive technologies, and other developers read the same order a visitor sees.

Design rules are declared once at the root as custom properties and referenced everywhere — change a token, and the change propagates. Layout runs on Flexbox and Grid with one consistent type scale. All interface copy is dictionary-driven, so a new language enters as a data file, not a rewrite.

Built to last

Nothing to patch, nothing to migrate, nothing borrowed — no rented platform, no stack of dependencies rotting quietly while you're not looking.

Hand-authored HTML, CSS, and JavaScript with no framework I couldn't justify, and no build tooling. Every style rule lives in one external system — no inline patches, no exceptions — which is what keeps the standard enforceable. No third-party dependencies means no forced migrations, no security-patch treadmill, and a payload small enough to stay fast without optimization theater.

Accessible by default

Usable with screen readers and keyboards, held to a recognized international standard from the first line of code — a requirement, not a repair.

WCAG AA held as a build gate: every meaningful image described in alt text, every form control paired with its label, landmarks distinguished with aria labels, visible focus styles so keyboard users always know where they are, and text contrast held at the 4.5:1 floor. Accessibility claims sit on this very page — which means they can be tested against it.

Governed, end to end

Speed came from AI; the standard stayed with me. Every build session runs under written rules and approval gates before anything ships.

Structured XML dispatches govern every build session — scope, constraints, and approval gates written before execution. Claude Code executes with Plan Mode previews reviewed before code lands; deployment follows hard rules with named commit intent — register, direct push, or a pull request with its link for manual approval — and authorship is logged to a single human author.

And when a stubborn spacing defect in the site's contact form outlasted the primary environment, a second AI tool, Gemini, rebuilt the component cleanly from zero for reintegration into the master codebase — the right tool, invoked when needed, under the same standard.

Act 06 · The Reflection

What fell, what bent, what stands.

The story reads clean in hindsight. It wasn't. Here is the journey in three houses, in the order I built them.

House of strawWhat collapsed first

My first prompts were plain text and good intentions. They decayed as builds grew, I chased every flag to closure, and template shortcuts gave me speed without ownership. It blew down — and falling taught me exactly what a foundation is for.

House of sticksWhat held, but bent

Iteration cycles ate whole sessions. One bug outlasted my main environment and needed a second tool. My documentation lived scattered across chats before a system existed. The structure held, barely — and every bend showed me where the next wall belonged.

House of bricksWhat stands

Versioned dispatches with approval gates. Skills that turn my intent into build-grade prompts. Project knowledge as the order I had historically lacked. Previews before code lands. And the habit of letting best judgment close the small flags — instead of overthinking them.

The sequel is already dispatched: per-case pages, the Spanish layer, and the next product rebuild. The houses get neighbors.
