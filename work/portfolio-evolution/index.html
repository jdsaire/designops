Act 01 · The Problem

Qualified on paper, unfamiliar in the room.

Start with the problem: good work nobody can place.

The reading

I apply for roles whose posts list what a candidate must have. No post lists what a candidate is expected to sound like.

Meeting every requirement is what gets an application considered; being understood is what gets it believed, and only the first is ever written down.

The credential

My own credentials are an MBA, a MicroMasters and a Microsoft specialization. Not one of them showed what I can actually build.

Research estimates work sample predicts job performance at about 3× more than education. A running page shows what I did with the diplomas

The claim

Three in four hiring teams say they receive AI-written applications – turning openings into odysseys for qualified candidates.

65% of hiring managers say skills are harder to verify as anybody can generate a fluent claim in seconds. Every figure here is backed up in public commit history.

The market

Employment in Lima, Peru has grown 22% since 2019, while the share of it held by workers under 25 has fallen by about a third.

Instead of contracting, local market is moving toward work that cannot be automated. That is the direction this website is built toward.

Sources: Sackett et al. (2022) on selection validity; Robert Half, November 2025, n = 2,000+; Deel Global Hiring Report 2026; INEI Encuesta Permanente de Empleo Nacional, May–July 2026.

Act 04 · The Architecture

Six decisions, four of them multi-page.

What held from the start, and what the multi-page build added.

Foundational

1) Vanilla HTML/CSS/JavaScript

No framework, no build step, no dependency I cannot read end to end.

Nothing to migrate when a major version lands. No security-patch treadmill. A payload small enough to stay fast on a mid-range phone over Peruvian mobile data — which is what most recruiters will use to open it.

Foundational

2) WCAG as a gate

WCAG AA held as a build gate, usable with screen readers and keyboards.

Every meaningful image carries alt text, every control is reachable by keyboard with a visible focus state, and contrast is verified in both themes rather than assumed.

Layout resolves at three declared breakpoints — 767px and below, 768 to 1023, and 1024 up. Those are the three the stylesheets actually declare, not a convention borrowed from a framework.

Multi-page

3) Three-level dictionaries

Site chrome, the strings every brief shares, and each brief's own copy, merged in that order.

A key lives at one level only, so a label every brief shares changes once, for all of them.

Every English file has a Spanish twin with the same keys, checked by script before each commit.

Multi-page

4) One chassis for every brief

Acts, poster panels, charts and dashboards, shared by every case brief.

Each case gets its own route and its own dictionary, so a recruiter can be sent to one page rather than to a scroll position. The cost: one defect in the chassis is a defect in every brief.

Multi-page

5) A gated dispatch pipeline

Every stage is written down as a dispatch before any code changes.

A written brief, then a prompt with preflight checks, then a plan I approve. The build stops at each gate on a local server until I release it with a set phrase, and it ends in a completion report. AI executes; the standard, the review and every merge stay with me.

Multi-page

6) Orchestration under a scope freeze

This build runs under a locked scope against overthinking.

Improvements that fall outside the written scope are logged in one line and not built. Decisions are made once, recorded as numbered rulings and not reopened. The discipline is the deliverable as much as the site is.

For more on the architecture, read the repository's README or browse my GitHub profile. You are reading the live site right now.

Act 06 · The Reflection

What the pipeline taught.

Three lessons from gates, rulings and records.

Gates

Stops that hold

A run stops at every gate until I release it with a set phrase. Review happens on the running page, in both languages, before anything merges.

Rulings and records

Decide once

Every decision becomes a numbered ruling in one log, and every edit I make on disk is recorded. The next session starts from the record, not from memory.

Verification

Measured, not assumed

Every figure on this page comes from a measurement or a named source. A headless check covers each page at three widths, two themes and two languages after every commit.
