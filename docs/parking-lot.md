## Logged tensions (Wave 5)

- Tag filter matching is **faceted**, not a strict global AND: a card must satisfy every category that has an active chip, and within a category any one chip suffices. The roadmap says multiple filters shortlist to "the intersection"; with a four-card pool a literal AND across every chip dead-ends on the second click (Banking + Airport would always return nothing). The intersection is therefore taken across categories, which is the standard faceted-search reading and keeps the pool navigable. Revisit if the card count grows enough to make strict AND usable.
- `assets/img/work/build-in-progress.svg` was renamed to `verify.svg` and is now Work Card 4's background. It was an orphan — referenced nowhere, and its filename described an in-progress treatment that PR-3 implemented in CSS instead. Card 4 needed art, it was the only unused asset in the set, and shipping a path named "build-in-progress" on a finished brief would have misread at source level. No capability lost; the in-progress treatment is the CSS one.
- Work cards are narrower at desktop going from three columns to four (about 319px wide against the previous 432px) — this width reduction is accepted and unchanged. **Height is no longer coupled to it as of PR-5**: card height had been `aspect-ratio`-driven, so it shrank by the same ~26% as width, which broke the hover overlay (title + summary + CTA no longer reliably fit). PR-5 gives `.work-card` an explicit `height: clamp(384px, 37.5vw, 540px)` at desktop (`work.css`, after the tablet breakpoint), matching the old 3-column height at every desktop width, and adds a `-webkit-line-clamp: 6` safety net to `.work-card__summary` as insurance. If a fifth card is ever added, the grid still needs a row break rather than a fifth column — width, not height, is the open concern now.

- `assets/img/work/build-in-progress.svg` was **not** used as the in-progress badge on the placeholder pages, despite the deployment naming it. Inspected: it is a 2.2 MB abstract purple gradient at 3279×4918, the same art family as `build.svg` / `control.svg` / `scale.svg` — a work-card background whose only in-progress semantics are in its filename. As a page badge it would communicate nothing while costing 2.2 MB per page. The pages instead carry a legible in-progress treatment built from existing tokens (dashed purple, uppercase, the established `.temporal` idiom). The asset remains available for a home work-card background if cards 2/3 should ever be marked in-progress there — not done, because it would make those two cards visually identical and their CTAs already lead to badged pages.
- Placeholder scaffold retains Brief 04's real measured figures (Act 05) and its staged-security material (Act 04). Both sit inside badged, dimmed scaffold acts on pages whose banner states the text belongs to another brief. Deleted outright when real copy lands; until then the badging is the only thing keeping those figures from reading as Brief 02/03 claims.

- Brief 04 Act 03 is a reconstructed effort chart, not a recorded sprint artifact: the v4 spec reserved this act for a future Gantt build, and the deployment authorized instantiating it. Story points express relative effort derived from the Wave 4 plan's phases and the completion report; the on-page caption states this plainly. If a real estimation record ever exists, replace the data object.
- Brief 04's `hero_read` now reads "7 min read", replacing the inherited-and-unverified "4 min read" that Copy v4's own fact register flagged and the spec's open item 7 authorized adjusting. Measured from the page: 1,517 surface words, ~6.3–7.6 min at 200–240 wpm; reveals add roughly two minutes more for a reader who opens them. Re-measure if the page's surface copy changes materially.
- Continuity card `../tuua-transfer/` 404s until the Wave 5 PR-3 placeholder pages land. Authored against the planned route, per the Copy v4 open item.
- **PR-5 root cause, for the record:** PR-1's file move left `assets/js/pages/home/nav.js` importing `../core/i18n.js` — correct from the pre-move location (`assets/js/home/`), broken from the post-move one, since it now needed `../../core/i18n.js`. A static ES-module import failure fails the whole graph, so `main.js`'s `DOMContentLoaded` handler silently never ran on Home — not just the language toggle, but the tag filter, carousel, evolution, contact, and ticker too. None of this was caught at the time because verification that PR (and every PR since) could confirm resource resolution and DOM-handle existence, but not execute JS — this specific bug only shows up at runtime. One-line fix in PR-5.
- **Expected, not a bug:** after PR-5, brief-page **body** copy (Acts, hero deck, cards) still renders in English when ES is selected, on all four brief pages. Brief 01's body ES dict is empty; Brief 04/placeholder body ES dicts are EN-mirrored — both already logged above, both awaiting the Wave 5.6 Sonnet pass. PR-5 only closed the CHROME-level gap (nav wordmark + CTA); the body-copy gap is unchanged and intentional.
